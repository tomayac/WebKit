WHAT THIS COVERS: that a written Cross-Origin Storage entry is still readable after the browser has been restarted. Nothing else tests this. The web-platform-tests suite has no way to restart a browser, and the unit tests in Tools/TestWebKitAPI/Tests/WebKit/CrossOriginStoragePolicy.cpp cover the on-disk record format without ever writing a file or starting a second process.

It is worth testing by hand precisely because it fails silently: an entry that did not survive is reported as an ordinary NotFoundError, which is exactly what a hash that was never stored looks like.

Checking whether this build has the feature enabled…

STEPS TO TEST:

  1. Load this page over https:, or from localhost or 127.0.0.1. Cross-Origin Storage is only exposed in a secure context, so a file: URL will report the feature as missing.
  2. Click write the entry. This stores a fixed 66-byte resource and immediately reads it back, so that a failure in step 4 can be blamed on persistence rather than on the write.
  3. Quit the browser completely and open this page again at the same URL. Closing the window is not enough: the registry lives in the network process, so a surviving network process would serve step 4 from memory and the test would pass without proving anything. Check that the browser's helper processes are gone before reopening.
  4. Click verify the entry.

TEST PASS: step 4 reports that the entry persisted, with the content intact.

TEST FAIL: step 4 reports NotFoundError (the entry did not survive), or reports a content mismatch (it survived but its bytes no longer hash to their own key, which verify-and-store exists to make impossible).
